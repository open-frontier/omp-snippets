# Changelog

## [Unreleased]

### Added

- **`ste100`** — a style pin for ASD-STE100, the controlled language of aerospace maintenance documentation. It defaults to about 80% of the specification and takes `strict` (or `100`) for the full rule set.
- **`html`** — a style pin that delivers explanations as one self-contained, offline HTML page: inline CSS and JavaScript, light and dark, interaction only where it aids understanding.
- **`create-snippet`** (alias `new-snippet`) — a one-shot helper that has the agent write a reusable snippet from your request: type the trigger, then describe the snippet in plain prose. It reads the README and the closest bundled example, picks a one-shot, pin, or role (a one-shot unless you ask for standing behavior), saves to `.omp/snippets/` unless you ask for a personal snippet, and never overwrites a file or silently takes over an existing name or alias. A pin with a parameter states what applies when the argument is blank. The agent then checks the loaded result — a one-shot's expansion, a pin's stored text, or a role's extracted body — by running this package's own registry and expansion code when it can and saying so when it cannot; that verifies mechanics, not that a model follows the text. The bundled catalog now has 29 examples.

### Changed

- **Enter toggles in the picker; Tab inserts.** On a pinnable row, `Enter` now toggles the pin in place, like `Right arrow`, which still works. On a role row, `Enter` selects the role immediately, or clears it when it is already active; the status line confirms it, and no history confirmation is added. `Tab` inserts the trigger text for every row, and `Enter` still inserts ordinary snippets. The hint line names both keys.
- **Parameterized pinnables toggle from the picker.** `max-chars`, `show`, and `ste100` were silently excluded from the picker toggle because they contain `$1`. They now pin with the argument blank, exactly like `::pin(name)`, so each snippet's documented default applies (280 characters, smallest useful format, about 80% STE). `AutocompleteItem.hasArgs` is removed.
- **Authoring docs mark the annotated template as illustrative.** Its trailing comments would become frontmatter values and the block-tag names it mentions inside its own text would fail the block parse, so copy a bundled example instead.

## [0.6.0] — 2026-10-19

### Added

- **Roles — `kind: role`.** A snippet can now define a standing operational role for the main conversation. Submitting its bare name (`::release-captain`) selects or refreshes it; `::unrole` (reserved exact trigger) clears it. Roles take no arguments — `::role-name(args)` and `::role-name<<...>>` never activate and are left as typed — cannot be pinned or carry an exclusivity `group`, and are gated to the main agent via the documented `ctx.agent.kind`, so subagent/child sessions never select, restore, or inject one.
- The active role is delivered every turn as an `<operational-role name="...">` block appended to the system prompt after `<pinned-styles>`, leaving the native system prompt untouched. Selection/clear add only a short history confirmation (`(role: <name>)`, `(role cleared)`, `(no role active)`) — never the body.
- A selection is snapshotted as a native entry, `pi.appendEntry("omp-snippets.role", { version: 1, role: { name, body } | null })`, written only on a role action, and restored from the newest record on the **active branch** on `session_start` / `session_switch` / `session_branch` / `session_tree`; `/new` starts with none. It rides the session's ordinary journal, inheriting its limits (a new ordinary session stays memory-only until its first assistant message; no `fsync`) — selection does not force a write to disk. Resume uses the saved body even if the role file changed or was deleted (with a reselect notice), and an unreadable record is ignored rather than resurrecting an older one.
- On a host that doesn't report `ctx.agent.kind`, roles are disabled with a one-time warning; snippets and styles keep working.
- **`category: <label>` frontmatter** — a display/order-only picker grouping label. `style`/`styles` (case-insensitive) group under Styles, an empty or absent label groups with the uncategorized snippets, and any other label becomes its own named group; a real role always groups as Role. The reserved value `role` (singular, case-insensitive, whitespace-trimmed; `roles` is an ordinary label) on a *pinnable* snippet marks it a **role-like pin** — it joins the leading picker tier and its name renders in the fixed purple, while expansion, pinning, lifetime, exclusivity, and the Right-arrow hotkey are untouched; on a non-pinnable snippet it is an ordinary label. Categories are not drawn as row badges — the grouping *is* the label, and apart from the role-like purple name no color encodes a category.
- **`description: <one line>` frontmatter** — an optional display-only picker description, exposed as `SnippetDef.description`. It never reaches expansion, `::pin`, or a role's injected body; when absent, the picker previews the snippet body instead. Either way the text is normalized to one line and capped at 60 code points (whole graphemes, word-boundary cut, trailing `…`), and the renderers only shorten it further to the width a row actually has.
- Category-based picker ordering, in three tiers — role-like rows first (real `kind: role` roles plus pinnable rows tagged `category: role`), then every other pinnable row (styles and behavioral pins alike), then ordinary non-pinnable snippets — within each tier: Styles, then other named categories alphabetically, then uncategorized last; within a category the active row (pinned snippet or active role) leads, then alphabetical. While filtering, relevance (exact > prefix > substring, aliases included) ranks first within a tier, then category, then active state, then alphabetical — within a tier, an unrelated active pin can no longer bury an exact match.
- Snippet definition problems (unknown `kind:`, `pinnable`/`group` on a role, empty role body, malformed block tags) surface as one `Snippet definition problems:` warning per session; a role with an empty body or malformed blocks is hidden from the picker and refused at selection.
- A muted hint line under the picker rows describes the highlighted row: `→ right arrow to toggle pin`, `→ conversation role · send to select`, or `→ active conversation role · send to refresh`.
- **Q&A-only guard (`guard: qa`)** — an opt-in guard a pinnable snippet can declare; the bundled Q&A (`examples/q&a.md`) opts in. While a guarded pin snapshot is active, native `tool_call` and `before_subagent_spawn` hooks reject non-read-only work with a visible reason and Q&A status. Only explicit unpinning releases it; prose approval and global auto-approval do not. Activation is refused while the agent is busy, owns running jobs, or cannot report that state. The guard follows the pin snapshot, not its filename or prose, and never changes native Plan/Execute or approval settings. See [Q&A-only guard](./README.md#qa-only-guard-guard-qa).
- **`bluf-insight`** — one opt-in style pin composes the existing `bluf` and `explanatory` definitions without copying their prompts. It shares `answer-delivery` with plain BLUF and Socratic delivery.

### Changed

- The nine bundled output styles declare `category: style`. The three durable behavioral pins (`careful`, `confirm-first`, `direct-evidence`) declare `category: behavior`, remaining green and sorting after Styles. Q&A retains `category: role`, its purple leading-tier placement, checkbox, and independent QA guard. One-shot snippets remain non-pinnable and retain the normal foreground.
- **Picker coloring and row layout.** Role-like names render in the fixed violet (`38;5;141`) — a `kind: role` snippet, or a pinnable snippet tagged `category: role`, and the active role included — and other pinnable names in the host theme's `success` green, while ordinary snippet names, all descriptions, and the pin mark use the normal foreground; there is no separate amber active-role color (the active role is identified by the `Role:` status line and the picker hint). Rows are compact single lines sharing one label column: `::name` plus its pin mark, padded to the widest label actually painted (the name is display-bounded to 28 cells, the mark follows it), then a three-space gap, then the description — so descriptions line up and a page of short names never reserves the 28-cell bound. At narrow widths the column shrinks before the description does, and a long name or description never wraps to a second line. Descriptions are one line, capped at 60 code points (an ellipsis marks a cut; the cut keeps whole graphemes and prefers a word boundary), then truncated to the row's actual terminal width; an authored `description:` replaces the body preview. The purple role-like name is a native ANSI node and each other pinnable name a native `s: 'success'` text span beside the description's native truncating text node, so the violet survives the native Tern renderer and the green resolves through the host theme token. Pinnables carry `📌`/`☐`, the selected row keeps its accent `▸ ` caret, and there are no category badges. Rows now order in three tiers — role-like rows (real roles plus role-categorized pins), then other pinnables, then ordinary snippets — regardless of pin state, in both the empty-query and the filtered picker; within each tier the category/relevance order, active state, and alphabetical order are unchanged. Right-arrow toggles without re-sorting, so selection stays stable.
- **Renamed `plan-mode` to Q&A (`q&a`).** Aliases are `qa` (including `QA`), `question and answer`, `ask-mode`, `plan-mode`, and `planning`; all target the same guarded pin. The old file is removed, not duplicated. Bare use remains advisory; pinning enforces read-only work until explicit unpinning. The name now distinguishes this pin from native `/plan`.
- Registered trigger names and aliases can contain `&` or a space-separated phrase. Expansion, arguments, pin/unpin, and picker acceptance resolve them consistently without consuming following prose or longer names.
- BLUF's repeated first-line instruction is trimmed. Explanatory insights are useful, non-obvious, and optional instead of requiring a fixed point count; the unsupported output-style parity claim is removed.
- Catalog copy is tightened without removing distinct snippets: delegation uses native subagent terminology and no unsupported `background: true` option, `chain`/`fanout` avoid repeated orchestration rules, and `report`/`show` keep their template and presentation contracts without redundant wording.

### Fixed

- **Guard snapshots cannot be downgraded by refresh.** Re-pinning after `guard: qa` is removed from a definition retains the active snapshot's QA marker and activation gate. Canonical unpinning prefers the actual pinned key, so a deleted definition or a shorter surviving name cannot trap the guard or remove an unrelated pin.
- Registry-aware role scanning now treats spaced aliases as complete heads and masks their argument spans. Nested bracket chains expand before an enclosing parenthesized argument is tokenized, preserving the established expansion order.

- **A reserved role name could be reached through an alias.** `findRoleActions` checked the *typed* trigger against the reserved names (`pin`, `unpin`, `pins`, `unrole`) before looking it up, so a role whose canonical name was reserved still activated under one of its aliases — e.g. a role named `pins` with alias `captain` was selectable via `::captain`. The check now also rejects the resolved definition's canonical name, so a reserved-named role is unselectable under any alias, case-insensitively, and stays out of the picker.
- **Picker color was dropped on omp's native Tern surface.** The picker handed its rows to `setWidget` as a plain `string[]`, which the native renderer converts to bare `Text` nodes; that conversion keeps only colors the host theme knows, so the fixed violet (`38;5;141`) had no token to map to and a colored row rendered uncolored on a native Tern terminal. Rows are now emitted through a widget component whose native descriptor carries the purple role-like name as a native ANSI node and each other pinnable name as a native `s: 'success'` text span next to the description's native `text` node (with `wrap: none` / `truncate: end`), so the fixed violet survives the native renderer while the host lays out and truncates the description to the actual row width. The `☐`/`📌` marks, the `▸ ` caret, ordering, hints, and lifecycle are unchanged; no new exports or host APIs are involved.
- **Unsupported role arguments are inert through every pass.** `::role(args)` and `::role<<...>>` for a recognized, selectable real role — canonical name, alias, case variant, or an `&`/phrase name — remain literal, preserving each recognized span as it appears in the current text. They are protected through the role pass, the pin-preprocessing pass, both expansion passes, and recursive rescans, including complete wrappers produced in ordinary body or argument text and recognized on a later pass; unclosed spans run to the end of the text under the existing scanner rules. Contents cannot pin or unpin, select or clear a role, expand an ordinary snippet, or contribute `<prepend>`/`<append>`/`<inject>` material; nested role wrappers protect their own contents, and a role-headed bracket chain feeds no ordinary sibling. This is phase-local protection, not cross-phase quoting: it does not undo an expansion already completed if later, separately generated text forms only a role head/opener. Existing bracket-first ordinary expansion and `::pins`/`::unpin`/`::pin` preprocessing order are unchanged. Valid top-level role commands and controls, ordinary expansion outside recognized spans, pin-pass ordering, group replacement, snapshot lifecycle, and pending inject are unchanged. The predicate is a selectable definition's real `kind: role`, not the display-only `category: role` label, so a Q&A argument wrapper is not caught by this rule.
- **Effective aliases follow the winning canonical definition.** Registry construction merged tiers key-by-key, so a project override of a canonical id could leave inherited personal or bundled aliases attached to the obsolete lower-tier definition: the picker previewed that old object while inserting the canonical trigger, which then expanded the new one. A post-merge reconciliation now re-points every inherited alias to the effective definition of its canonical id — body, `kind`, `pinnable`, `group`, `category`, `guard`, and `description` — while an explicit higher-tier claim on the alias key still wins. When a higher tier overrides the same canonical id, that definition wins and the aliases re-point to it; when a different-named definition claims a canonical key, the shadowed definition's inherited aliases are dropped with it rather than redirected, and no stale object or canonical picker row survives. One effective picker row per effective definition, labeled with its canonical id, keeps the preview, inserted trigger, raw alias invocation, and Right-arrow pinning in agreement; invalid higher-tier definitions remain diagnosed rather than falling back to an older body. Bundled < personal < project precedence and first-key-wins within a directory are unchanged.
- **Q&A keeps one stable pin identity.** Every alias that resolves to the guarded Q&A canonical id addresses the same pin entry, so `::pin(...)`, `::unpin(...)`, the picker's Right arrow, the status line, and group replacement all share that entry; unpinning through an alias cannot leave a duplicate behind. The snapshot rules are preserved and now documented: the expanded body and any `guard` marker are captured at activation, group replacement happens once at activation, refresh cannot downgrade an active guard, and explicit canonical unpinning still works after the defining file disappears without removing an unrelated pin that shares a shorter name.
